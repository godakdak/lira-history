# LIRA 진단이력 — 웹 버전 + iPad 앱 (데모)

아이폰·아이패드·PC 브라우저에서 같은 주소로 열고, **전국 본부 담당자가 올린 측정 데이터가 한곳(중앙 저장소)에 모입니다.**
iPad·iPhone용 앱(Swift Playgrounds)은 이 웹 화면을 그대로 띄우는 앱이라 기능·데이터가 같습니다 (아래 'iPad 앱' 참고).

- 화면: 지도 · 진단이력 · 추가 입력 · 설정 / 구간 상세 · 새 진단(현장) · 진단 상세(사무실) · Signature 전후·상간 비교
- 새 기능: LIRA 측정 파일(.lira·.anl·.out·.sdt·.pbd)을 그대로 불러오기 → 상·DeltaG·긍장·분석대역 자동 입력, LIRA 분석값 그대로의 Normalized 기준선(0 dB)·1SD
- 로그인 없음 (데모)

## 구조

```
GitHub Pages (무료)  ── 화면(HTML·JS) 제공
        │
        ▼
Supabase (무료)      ── 데이터베이스(구간·진단) + 파일 저장소(사진·스펙트럼·LIRA 원본)
```

GitHub Pages는 파일을 보여주기만 하고 데이터를 저장할 수 없으므로, 저장은 Supabase 무료 플랜을 씁니다.
Supabase를 연결하지 않으면 **로컬 모드**(그 브라우저에만 저장)로 동작하므로, 먼저 화면만 확인해 볼 수도 있습니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 시작 페이지 |
| `app.js` | 화면과 동작 전체 |
| `signature.js` | Signature 계산 (FFT·윈도우·감쇠보정·Normalized) |
| `lira.js` | LIRA 측정 파일 읽기 |
| `store.js` | 저장소 연결 (Supabase / 로컬) — 나중에 한전 서버로 옮길 때 이 파일만 교체 |
| `config.js` | **Supabase 주소·키 입력하는 곳** |
| `styles.css` | 화면 모양 |
| `seed.json`, `seed_susan6.jpg`, `seed_susan9.jpg` | 이관 자료(예시 데이터) |
| `icon.png` | 아이콘 |
| `setup.sql` | Supabase 초기 설정 스크립트 (사이트에는 올리지 않아도 됨) |

## 1단계 — Supabase 준비 (약 10분)

1. https://supabase.com 가입 → **New project**
   - Region: **Northeast Asia (Seoul)** 권장
   - Database password는 아무 값이나 (앱에서는 쓰지 않음)
2. 프로젝트가 만들어지면 왼쪽 메뉴 **SQL Editor** → **New query**
3. `setup.sql` 내용을 통째로 붙여넣고 **Run** → 마지막에 `sites_count 0`, `diagnoses_count 0`이 나오면 성공
   (테이블 2개, 파일 저장소 `lira`, 데모용 접근 권한, 실시간 반영이 한 번에 설정됩니다. 여러 번 실행해도 안전)
4. 주소와 키 복사
   - **Project URL**: `https://xxxxxxxx.supabase.co` (대시보드 상단 **Connect** 버튼 또는 Project Settings → Data API)
   - **Publishable key** (`sb_publishable_...`) 또는 **anon public** key (Project Settings → API Keys)
   - ⚠️ `secret` / `service_role` 키는 절대 넣지 마세요.

## 2단계 — config.js 수정

```js
window.LIRA_CONFIG = {
  SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
  SUPABASE_KEY: 'sb_publishable_xxxxxxxxxxxx',
};
```

## 3단계 — GitHub Pages에 올리기

1. GitHub 로그인 → 오른쪽 위 **+** → **New repository**
   - 이름 예: `lira-history`, **Public** 선택 (무료 계정의 Pages는 Public 저장소에서만 됩니다)
2. 저장소 화면에서 **Add file → Upload files** → 위 표의 파일들을 폴더 없이 그대로 끌어다 놓고 **Commit changes**
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main** / **(root)** → **Save**
4. 1~2분 뒤 `https://<깃허브아이디>.github.io/lira-history/` 로 접속
   - 첫 접속 시 이관 자료(36개 구간·37건)가 중앙 저장소에 자동으로 채워집니다.
   - 설정 탭 → 데이터 저장소가 **중앙 저장소 (Supabase)** 로 보이면 연결 성공입니다.
5. 아이폰: Safari로 열고 **공유 → 홈 화면에 추가** 하면 앱처럼 쓸 수 있습니다.

파일을 고친 뒤에는 같은 방법으로 다시 올리면(같은 이름 덮어쓰기) 몇 분 안에 반영됩니다.

> **업데이트할 때는 바뀐 파일만 고르지 말고 `index.html` `app.js` `signature.js` `lira.js` `store.js` `styles.css`를 항상 함께 올리세요.**
> 일부만 올라가 파일 버전이 섞이면 화면 위에 빨간 경고(⚠ 파일 버전이 맞지 않습니다)가 나옵니다. 그때는 위 6개 파일을 다시 올리고 Ctrl+F5로 새로 여세요.

## 사용 흐름

**현장 (아이폰)** — `＋ 새 진단`
1. 명판·전경 사진 (보관함 또는 촬영). ★ 대표사진의 GPS로 위치를 잡고, 반경 500 m 안의 기존 구간을 찾아 줍니다.
2. 기존 구간 선택 또는 새 구간 등록 → 측정 상·측정단·측정자 → **현장 저장**

**사무실 (PC)** — `추가 입력` 탭에서 빠진 항목이 있는 진단을 열고
- **📂 LIRA 측정 파일 한 번에 불러오기**: 측정 폴더에서 같은 이름의 `.lira .anl .out .sdt .pbd` 파일을 여러 상 한꺼번에 선택(또는 끌어다 놓기)
  - 상: 측정 설명의 `Phase A/B/C/N` → 없으면 파일 이름 → 그래도 없으면 물어봄
  - DeltaG(.out), 긍장·분석대역(.anl), LIRA 정규화 기준선(.sdt) 자동 반영
  - `.lira`는 필수, 나머지는 선택. 다만 LIRA에서 **프로브 보정(EnableProbComp)을 켜고 측정했다면 `.pbd`가 꼭 있어야** LIRA와 같은 Signature가 나옵니다. `.anl`이 없으면 직렬 인덕턴스 보정을 못 합니다.
  - 폴더의 같은 이름 파일 5종을 모두 고르는 것을 권장합니다.
- 기존 방식의 스펙트럼 텍스트(.txt)도 그대로 됩니다 (파일 이름 끝 `_A` `_B` `_C` `_N`으로 상 구분).
- **클립보드 붙여넣기**: LIRA에서 스펙트럼을 클립보드로 복사한 뒤
  - 해당 상의 **📋 붙여넣기** 버튼 → 그 상에 바로 저장 (처음 한 번 브라우저가 클립보드 접근 허용을 물어봄)
  - 또는 진단 화면에서 **Ctrl+V** / 스펙트럼 칸의 **📋 클립보드 붙여넣기** → 어느 상인지 선택
  - 이미 다른 상에 넣은 같은 측정을 다시 붙여넣으면 경고합니다 (다음 상 복사를 잊은 경우).

**잘못 입력한 구간(현장) 정보 고치기** — 구간 화면에서
- **✎ 구간 정보 수정**: 구간명·본부·사업소·시점/종점 설비명·전산화번호·지중/해저·선종·규격·긍장·제조년월·제조사
- **📌 위치 다시 지정**: 지도에서 위치를 직접 맞춤
- **이 구간 삭제**: 그 구간의 진단 기록(사진·스펙트럼 포함)도 함께 삭제됩니다. 진단이 있으면 `삭제`를 입력해야 실행됩니다.
- 진단을 엉뚱한 구간에 넣었거나 이미 있는 구간을 새로 등록했다면: 진단 화면 아래 **⇄ 다른 구간으로 옮기기** → 맞는 구간 선택. 옮긴 뒤 빈 구간이 남으면 삭제할지 물어봅니다.

**분석** — 구간 화면 → `Signature · 전후 비교`
- 전후 비교(같은 상, 여러 날짜) / 상간 비교(같은 날짜, A·B·C·N)
- 분석 대역폭 슬라이더, Normalized + 관심·주의 기준선, 접속지점 지정·비교표, 반전(저장됨), VR 직접 입력(TDR m/μs 함께 표시)
- Normalized ON/OFF는 LIRA의 Norm ON/OFF와 같습니다. ON(기본): 감쇠 보정 + 0 dB 기준선, OFF: 보정 없는 원 신호.
- **Variance** (Normalized ON일 때): LIRA Signature 탭의 Variance와 같습니다. 0 dB 기준선 = 평균 + Variance × SD, 0 ~ 2를 0.1 단위로 조절(기본 1, LIRA 분석값이 있으면 그 Variance). 화면 표시만 바뀌고 판정에는 영향이 없습니다. '현재 조건을 구간 기준으로 저장'하면 진단 화면 미리보기에도 쓰입니다.
- 0 dB 기준선은 LIRA 분석값(.sdt)이 있으면 그대로, 없으면(텍스트·클립보드) LIRA 방식 근사(평균 ±1.5 SD 밖 값 제외 후 평균 + 1 SD, 보고서 55건 기준 중앙값 0.5 dB 차이)로 계산합니다.
- 대역폭이 LIRA 분석대역과 같고(±2%) 윈도우가 4 Term B-H이면 0 dB 기준선·1SD는 **LIRA 분석값**(.sdt)을 그대로 씁니다. 범례에 `기준선 LIRA 분석값`으로 표시됩니다.

---

**판정 (한국형 잠정기준)** — 설정 탭에서 바꾸며, 저장하면 전국 모든 사용자에게 바로 적용됩니다
- DeltaG: 관심 기준 이상 → 관심, 주의 기준 이상 → 주의 (기본 20 / 25)
- 국부신호 (**접속지점 제외**): 감쇠 보정 신호가 **케이블 구간 평균 + k × SD** 를 넘으면 판정 — 관심 기준 SD 초과 → 관심, 주의 기준 SD 초과 → 주의 (기본 2 / 3 SD)
  - **평균·SD는 접속지점 반사를 빼고 다시 계산**합니다. LIRA와 같은 구간([2×분해능, 0.9×긍장])·같은 계산(평균 ±1.5 SD 밖 값 1회 제외)에서 접속지점 반사만 뺀 것이라, 접속개소가 많아도 기준이 올라가지 않습니다.
  - 접속지점 반사 = 지정 위치 ±1.5×분해능에서 시작해 반사 곡선이 끝나는 첫 골까지(최대 ±3×분해능). 뷰어의 음영이 이 범위입니다.
  - 국부신호를 찾는 구간에서도 접속지점 반사와 근단·종단 반사의 꼬리(2×분해능 ~ 첫 골, 최대 4×분해능)를 뺍니다.
  - 표시용 0 dB 기준선(LIRA Normalized, Variance)과는 따로 계산하므로 Variance를 바꿔도 판정은 그대로입니다.
  - 스펙트럼을 올리거나 진단 화면을 열 때 자동 계산·저장됩니다 (구간 기준 대역폭 → LIRA 분석대역 → 가이드라인 순). 진단 화면의 SD 값에 마우스를 올리면 기준 평균·SD가 보입니다.
  - Signature 뷰어의 '관심 · 주의 기준선 표시'를 켜면 같은 기준선이 보입니다. 여러 곡선을 겹치면 평균 기준선 한 개씩만 표시됩니다. Variance가 커서 0 dB 기준선이 관심·주의선보다 높아지면 그래프 아래 끝에 '0 dB 아래'로 표시됩니다.
- 접속지점 (**접속지점 신호만 따로 비교**): 접속지점은 원래 반사가 크므로 절대 크기가 아니라 '다른 것보다 얼마나 큰가'로 봅니다.
  - 접속지점 신호 S = 접속지점 ±0.75×분해능 안의 최댓값을 감쇠 보정한 크기(dB). 케이블 구간 평균 + 1 SD(접속지점 제외) 아래면 '신호 없음'(표에 `≤` 표시, 판정 안 함).
  - 상간 편차 = S − 같은 접속개소 다른 상들의 중앙값, 개소간 편차 = S − 같은 상 다른 접속개소들의 중앙값
  - 편차 = 둘 중 큰 값. 관심 기준 이상 → 관심, 주의 기준 이상 → 주의 (기본 **6 / 10 dB**: +6 dB = 반사 크기 2배, +10 dB ≈ 3배)
  - 상의 접속지점 판정 = 그 상에서 편차가 가장 큰 접속개소. 진단 화면에 `+3.5 dB · J2 478 m`처럼 표시됩니다.
- **접속지점 지정**: 구간 화면 → Signature 뷰어 → '접속지점' 칸
  - 그래프를 눌러 커서를 접속지점 신호 위에 두고 **＋ 커서 위치에 추가** (근처 피크로 자동으로 맞춤), 또는 거리(m)를 입력하고 **추가**
  - 접속지점은 **구간 시점 기준 거리**로 구간에 저장되어 그 구간의 모든 진단에 쓰입니다. 종점 쪽에서 측정한 데이터는 범례의 **반전**을 켜 두세요(진단 기록에 저장).
  - 표에서 상·날짜별 접속지점 신호와 편차를 비교하고, 잘못 지정한 것은 **삭제**합니다.
- 진단 종합 판정 = 상별 DeltaG·국부신호·접속지점 중 가장 나쁜 것.
- 지도 색: 판정값이 있는 가장 최근 진단 기준으로 주의(선홍) · 관심(노랑) · 양호(초록) · 판정 없음(회색). 구간 화면의 '★ 지도에서 강조'를 켜면 별과 금색 테두리로 표시됩니다.
- **업데이트 시 Supabase에서 새 setup.sql을 한 번 더 실행하세요** (판정 기준 저장용 표 `app_settings` 추가, 기존 데이터는 그대로). 실행하지 않으면 기준이 그 브라우저에만 저장됩니다.

## iPad 앱 (Swift Playgrounds)

`LIRA History.swiftpm` 은 이 웹 화면(같은 주소·같은 Supabase)을 앱으로 띄우고, 아래 기능만 iPad 기능으로 연결합니다. 웹을 고치면 앱도 다음 실행 때 같은 버전이 됩니다(앱을 다시 설치할 필요 없음).

| 기능 | 브라우저 | iPad 앱 |
|---|---|---|
| 보관함 사진 | iPadOS가 위치(GPS)를 빼는 경우가 있음 | 원본의 촬영 위치·일시를 함께 읽음 (EXIF → 없으면 사진 앱 위치) |
| LIRA 측정 파일 | 파일 선택 창이 .lira를 흐리게 막는 경우가 있음 | 파일 앱(USB·iCloud·네트워크 드라이브)에서 여러 개 선택 |
| 현재 위치 | 웹 위치 확인 창 | 앱 위치 권한 한 번 |
| 클립보드 붙여넣기 | 브라우저에 따라 막힘 | 📋 버튼으로 바로 (iPadOS '붙여넣기 허용' 확인) |
| 내보내기(CSV·JSON) | 다운로드 | 공유 시트 → 파일에 저장·메일·AirDrop |

설치: `LIRA_History_iPad.zip` 을 iPad의 파일 앱에 저장 → 눌러서 압축 풀기 → `LIRA History.swiftpm` 을 누르면 Swift Playgrounds에서 열림 → ▶ 실행. 처음 쓸 때 사진·위치 권한을 허용하세요. 인터넷 연결이 필요합니다.
웹 코드에서 앱 연결은 `window.LIRA_NATIVE` 가 있을 때만 동작하므로 일반 브라우저 동작은 그대로입니다.

## 꼭 알아 둘 점 (데모 한계)

- **로그인이 없습니다.** 웹 주소를 아는 사람은 누구나 보고, 고치고, 지울 수 있습니다. 주소는 관계자에게만 알리고, 시연 단계에서는 민감한 실데이터를 최소화하세요. config.js의 키는 원래 공개되는 값이라 노출 자체는 정상입니다.
- 설정 탭의 **예시 데이터로 초기화**는 중앙 저장소의 모든 입력을 지웁니다 (`초기화`를 직접 입력해야 실행).
- **Supabase 무료 플랜 한도**: 데이터베이스 500 MB, 파일 1 GB(사진은 긴 변 1600px로 줄여 저장 → 약 3,000장), 월 전송량 5 GB, 파일 1개 50 MB.
- **1주일 동안 아무도 접속하지 않으면 Supabase 프로젝트가 일시 정지**됩니다. 화면에 "데이터를 불러오지 못했습니다"가 나오면 Supabase 대시보드에서 **Restore/Resume** 하세요(데이터는 남아 있음).
- 같은 진단을 두 사람이 동시에 고치면 **나중에 저장한 쪽**이 남습니다.
- 다른 담당자가 저장하면 열려 있는 화면에 자동 반영됩니다. 반영이 늦으면 설정 → **최신 데이터 다시 불러오기**.
- 아이폰 Safari에서 보관함 사진을 고르면 GPS 정보가 빠지는 경우가 있습니다. 그때는 **📷 촬영**(촬영 시 기기 위치 기록)이나 **◎ 현재 기기 위치**, **📌 지도에서 지정**을 쓰세요. HEIC 사진은 PC 브라우저에서 열리지 않을 수 있습니다(JPEG로 올리기).
- 지도는 OpenStreetMap을 씁니다.

## 실제 운영으로 넘어갈 때

1. Supabase Auth로 로그인 추가 → 본부별 권한 정책(RLS)으로 `setup.sql`의 "demo" 정책 교체
2. 한전 내부 서버로 옮길 경우 `store.js`만 새 서버 API에 맞게 바꾸면 화면 코드는 그대로 쓸 수 있습니다.
3. 판정 기준이 확정되면 설정 화면의 입력을 막고 값을 고정합니다 (`app.js`의 `DEFAULT_CRITERIA`).
